# 局部 · 图片批注与 Codex 局部修改工具

给 AI 生成的 PPT 页面、海报做局部修改：在网页上框出要改的地方、写清要求，点「去 Codex」交给 Codex 修改，结果自动回到网页。

现有「图片修改」继续使用；新增「PPT 专区」可直接导入 `.pptx`，按对象分析、集中确认、批量修改后另存新的 PPTX。两者都只在本机运行，使用 Codex 桌面内置图片能力，不接 GPTNB 或额外付费图片 API。

和让图片模型重画整张图不同，这个工具**只把选区内的像素贴回原图，选区外像素与原图逐像素一致**，由程序检查「范围外变化像素数为 0」后才算完成。反复修改不会让其他区域累积噪点。

## 环境要求

- **Windows**：「去 Codex」通过 `codex://` 链接唤起 Codex 桌面版，目前只在 Windows 上实现和验证过。
- **Codex 桌面版**：图片修改由发送后的 Codex 聊天完成，使用它内置的图片编辑能力，不需要额外的图片 API Key。
- **Python 3.10+**。
- **PPT 专区另外需要 Windows Microsoft PowerPoint 和 pywin32**。本机通过 PowerPoint COM 只读渲染，优先沿用本机字体和原版式；缺少依赖会显示具体错误，不提供伪造预览，不上传到转换服务。未实现 WPS / LibreOffice 回退。

```powershell

```

或运行 `./start.ps1`。浏览器打开 <http://127.0.0.1:47831>。使用期间保持这个窗口开着，关闭即停止服务。服务只监听本机，图片、批注和历史版本都保存在本地 `data/` 目录，关机不会丢失。

## 完成一轮修改

顶栏的 4 步进度会高亮当前该做的一步。

1. **导入图片**：PNG / JPG。原图永久保留，另存无损 PNG 作为比较基准。
2. **标出要改的地方并写要求**，两种方式：
   - **框选**：在图上拖出矩形，在右侧写「要改成什么」。
   - **改图中文字**：点画布工具栏「识别文字」，每行显示为「原文 → 改成…」，填写新内容后点「加入批注」，会自动生成选区和修改要求。
   - 只想改选区里的一部分时，用画布上方的「画笔」在红框内涂出允许修改的范围，没涂到的像素保持原样。
   - 可加一条「整图共同要求」，比如保留原字体和配色。
3. **去 Codex 点发送**：点「去 Codex」，会打开 Codex 并预填好指令，检查后**在 Codex 里点发送**（工具不会替你自动发送）。按钮不可用时，悬停可查看原因。
4. **自动显示结果**：Codex 修改并通过像素检查后，网页自动载入新版本。可以前后滑动对比、恢复历史版本、导出原尺寸 PNG（不带批注框）。

快捷键：B 框选、M 画笔、E 擦除、H 平移，空格临时平移，滚轮缩放，Delete 删除选中的选区。

如果点击「去 Codex」后没有发送、额度不足，或关机后草稿丢失，右侧底部会保留任务恢复入口。点「重新打开 Codex」可用原任务重新预填，仍需自己发送；点「取消任务，继续编辑」可解除提交限制，批注和历史记录保留。切到其他图片也能处理挡住提交的旧任务。已领取但中断的任务也可以取消，取消后旧任务不能写回结果。

## 工作原理

```text
网页框选 → 保存任务（原图坐标、要求、编号预览）→ 打开 Codex 并预填
        → Codex 按专用 Skill 裁出参考图 → 内置图片编辑 → 检查对齐
        → worker.py 只把允许范围的像素贴回原图 → 校验范围外 0 像素变化
        → 保存新版本 → 网页自动更新
```

- 专用 Skill 在 `.agents/skills/local-image-edit/SKILL.md`，规定 Codex 的执行步骤。`worker.py` 提供 claim / prepare / normalize / compose / fail 等命令。
- 参考裁图由后台自动扩展，给模型提供对齐依据；允许修改范围是红框或画笔区域。界面只显示实际修改范围，不显示参考边距输入框或蓝色参考虚线。
- 模型返回的图片尺寸或位置有变化时，不会直接缩放贴回，只能通过有锚点证据的配准纠正；配准不可靠就判失败，可以调整选区或要求后重试。

数据目录：

- `data/store.sqlite`：任务、版本、图片和草稿。
- `data/images/`：原始上传文件和各版本 PNG。
- `data/tasks/任务ID/`：`task.json`、`批注.md`、编号预览、参考裁图、遮罩、模型输出与 `validation.json`。

## 限制

- 一次最多 20 个不重叠的选区；单个参考裁图超过 3840 像素时需要拆分选区。
- 平面底色上的单色文字效果最好。纹理、渐变、照片背景上的文字可能因无法可靠对齐而失败。
- 像素检查只能保证选区外不变，选区内改得好不好需要人看。执行任务的 Codex 会查看模型结果，有明显错位、接缝或文字放不下时判失败。
- 任务按顺序执行。修改期间如果你恢复了别的版本，旧任务的结果会保存为分支版本，不会覆盖你的新操作。

## PPT 专区

启动命令仍为 `python server.py --port 47831`，打开 <http://127.0.0.1:47831/ppt.html>，也可从顶栏「图片修改 / PPT 专区」切换。已有服务需要重启 Python 进程加载后端新增功能。

1. **导入 PPTX**。永久保存上传原文件，后台检查并使用本地 PowerPoint 生成真实缩略图。仅接受 `.pptx`；其他格式先用 PowerPoint 转换。上传上限 512 MiB、解压总量 2 GiB、单个成员 256 MiB、单个 XML 16 MiB、10000 个 ZIP 成员、300 页；拒绝危险路径、符号链接、重复成员、加密、宏和 XML 实体。文件直接流式上传并显示实际上传进度，不转 Base64；PPT 包按需读取，另存和下载分块处理。
2. **填写总体与逐页要求**。在页面预览下的「总体修改要求」填写本轮修改，例如「全篇年份改为 2026，保留其他布局」。针对当前页的要求填在「第 N 页要求」，翻页时自动切换内容，有要求的缩略图会显示圆点；下方「逐页要求 N 页」可展开跳转或删除。默认选中全部页面，也可在左栏取消全选、勾选缩略图，或展开「已选 N/M 页」输入 `3,5,8-12`。给未选页写要求会自动选中，取消选择有要求页时会先确认清除。只有逐页要求时，只分析其中有要求的已选页；旧草稿中的固定格式要求会自动恢复到对应页。
3. **需要精确指出位置时直接框选**。点击页面预览上方「框选修改」，在页面拖出矩形，然后在下方框选批注写这处要求。可切换页面继续添加多个框，和上方整段方案一起提交，不必先跑分析。框选是定位提示，后续按真实文本、表格、图片对象整理成实际修改计划；不会将页面截图当作原图片直接回贴。总体要求、逐页要求、页码和跨页框选在此浏览器按 PPT 版本保存；旧草稿按内容恢复到总体或逐页输入。
4. **点击「让 Codex 分析要求」**。按钮在总体要求框正下方。桌面链接预填分析指令，仍需在 Codex 点击发送。Codex 将全部方案与跨页框选整理为逐页、逐对象修改项，读取真实对象结构与 OCR，再实际查看页面与源图。未涉及的页面说明保留原因，不制造无意义待确认项。分析阶段不会生成图片。
5. **集中确认计划**。清单默认显示页码、类型、原内容到目标内容及确认勾选；点击卡片或「编辑」后展开字段和「查看范围」，技术依据与对象范围继续折叠。可批量确认明确项，或逐项取消、修改新内容与单项要求。「查看范围」切到该页。新分析协议中，更换原内容、目标对象、单元格或图片源范围需重新整理清单，防止沿用旧视觉定位；可在页面框选和修改要求中说明新目标。修改要求或添加、调整框选会使整批旧确认失效，需要重新整理或确认。模糊要求、多个匹配、找不到明确目标和不支持的对象标为「需要确认」。
6. **执行已确认项，去 Codex**。第二次在 Codex 点发送后，一个执行聊天可串行处理所有确认项，无需逐页发送。原生文本直接修改，图片走现有参考裁图、真实图片工具、配准、遮罩回贴。网页自动显示逐项状态与错误。
7. **查看结果、导出新 PPTX**。提供每一页的前后对比、版本列表和 JSON 修改清单。方案未涉及的保留页不记为失败，未完成的实际修改项会显著标注。原文件、各步中间版本、原模型输出、配准与验证记录保留。

### 编辑支持范围与保真边界

分析先查看完整页面渲染，再查看单个图片对象原图。`context` 返回有类型的 `visual_inputs`、逐页 `visual_reference` 和原生文字索引；`full_slide_composite` 包含叠加文字与形状，`single_picture_source` 不包含它们。底图有旧标题不意味着用户看到的标题不可编辑。原生标题优先定位原生对象；当前原生路径支持改字并保留样式，字体、纹理填充等样式优化仍需列为待确认，不把它转成整页生图。

分析提交必须绑定 `context_sha256`，逐页 `page_reviews` 绑定整页 PNG 哈希，每项 `target_review` 记录可见目标与上层候选关系。`ppt_worker.py locate` 按候选修改区域、z 和保守旋转边界返回上层对象；`overlays` 只是相交候选，不证明完全遮挡。已知上层原生文字与图片改字目标冲突、候选遗漏、资源或预览哈希不符会被程序拒绝；明确遮挡或无法可靠定位需改选对象或写 confirm。透明框与装饰的相交不会自动排除图片。

程序验证文件绑定、对象关系与已知文字匹配；模型必须实际查看完整渲染，判断字形归属、透明度和遮挡。视觉说明标为 `model_report_only_not_program_verified`，它不是「程序证明模型已查看」。技术依据展开后显示这一区别，仍由用户对照整页集中确认。新提交不接受缺少上下文与视觉定位字段的旧格式；已冻结的历史执行任务保留原协议，不迁移或自动恢复。

| 内容 | 第一版行为 |
| --- | --- |
| 有明确自身坐标的原生文本框 | 修改唯一匹配的同段文字，支持跨格式运行片段，尽量保留字体、字号、颜色和段落属性，保持可编辑 |
| 普通表格 | 定位具体行列单元格，保留表格；合并单元格、旋转/翻转表格暂不编辑 |
| PNG / JPG 图片对象 | 原图局部修改，支持普通矩形图片的缩放、裁剪、旋转和翻转；只给确认的图片实例创建新资源关系 |
| 混合页面、图片上叠字 | 分对象处理，结合层级与重叠关系定位，避免重复修改 |
| 图表、SmartArt、组、嵌入对象、继承布局坐标 | 保留原对象，标为需要确认；不自动拆组或整页栅格化 |
| 非矩形、平铺、3D 图片、外扩裁剪、非默认填充矩形 | 暂不直接编辑 |
| 备注、主题、超链接、动画、切换、媒体、Office 扩展 | 采用 OOXML 小范围补丁，不用 python-pptx 重存；未改 ZIP 成员的内容逐字节保留。未逐类验证所有复杂播放行为，不承诺任意 PPT 无损 |

原生文本验证与图片验证分开：文本改后由 PowerPoint 重新打开，检查新增换行、溢出、上层遮挡和页面范围外变化，失败则保留原项并标为待调整，不缩小整页字号。当前保守策略也会拒绝原有溢出、复杂遮挡或无法测量的文本，不自动重新排版。

图片源像素允许范围外变化必须严格为 **0**，必须保留有效几何配准证据；配准失败不能应用，不降低阈值。页面渲染另做修改多边形外变化检查，边缘仅留 3 像素采样保护带，这不放宽图片源像素的零变化标准。逐项验证未改页面渲染一致，并检查未改 OOXML 成员没有变化。

页面采样保护完整覆盖多边形边缘及四角，用实际多边形向各方向扩展 3 个渲染像素，避免旧描边方法遗漏角点。保护带内的变化数量和最大颜色通道差异单独记录，不冒充源像素变化；保护带外仍拒绝。源图片仍逐像素检查允许范围外变化为 0，没有按「总数少」放行图片越界或几何失败。

渲染验收使用同一批次的「基准 PPT、候选 PPT、再次基准 PPT」，三次只读打开共用本地 PowerPoint 队列锁。两次基准必须逐像素一致，候选的未修改页也必须逐像素一致；渲染文件绑定输入哈希和完整页序。导入时的历史预览只用于展示，若与新基准不同会记录差异，不直接作为验收基准，也不覆盖旧预览。重复基准自身不稳定时仍拒绝应用，不提高容差。前后对比采用通过验收的同批基准，避免把旧预览差异展示成修改效果。

成功数为 0 时显示「未完成（0 项成功）」和「导出文件保留原内容」，任务记为失败。只有至少一项成功且仍有未完成项时才显示「部分完成」。此前保存的 0 成功历史版本同样按未完成展示。

### 取消、重试与恢复

任务区可取消尚未完成的队列，也可恢复中断。进度、基准、输入文件和计划绑定；恢复只处理未完成项，不重复已经成功的图片生成或应用。同一图片上的多个修改按计划顺序使用上一步结果，重叠区域也不会并行回贴。

「恢复中断」会使旧 PPT 执行令牌失效；没有自动重试或自动唤醒聊天。恢复时优先复用已保存的模型文件。若上次生成是否成功无法判断且没有文件，明确报「生成结果不明」，不自动重复生图。修改要求或版本后应重新分析、重新确认，旧任务不能覆盖新版本。

已完成的图片子任务可在其他页面成功后继续复用，但必须证明原基准属于本任务、目标页及其关系文件逐字节一致、图片对象和源图片完全一致；目标页、源图或选区基准已变时拒绝复用，不重新绑定旧模型冒充新结果。

当前桌面交接沿用已验证的 `codex://new?path=...&prompt=...` 方式。网页不会控制当前聊天、注入消息或自动点击发送。新增 PPT 两阶段任务的网页交接在隔离测试中被拦截，未再单独进行一次新桌面聊天的人工点发送验收。

### PPT 文件与执行协议

- `data/ppt/decks/<id>/original.pptx`：永久原文件、原始渲染与图片资源。
- `data/ppt/jobs/<id>/`：任务、上下文/OCR、计划、中间 PPTX、逐项渲染和验证。
- `data/ppt/versions/<id>/`：另存的结果 PPTX 和修改清单。
- 图片子任务继续保存在 `data/tasks/<id>/`，从单图图库隐藏，保留原始模型文件、参考图、配准和零像素验证。
- Codex 任务说明在 `.agents/skills/local-ppt-edit/SKILL.md`；`ppt_worker.py` 提供 claim / context / locate / plan / advance / record-model / accept-image / fail-item / publish 命令。文件和 PPT 内容都是数据，不能覆盖执行规则。

### 小选区的参考图保护

参考边距是最小值，参考图自动扩展到至少 1024×1024 原像素，并尽量以选区为中心保留周边内容。小原图会补白；实际可修改矩形或画笔遮罩不扩大。prepare 会报告选区外参考特征，缺少依据时先提示调整，配准成功仍须模型输出匹配验证。若只写「修复文字」，建议补充准确目标文字以减少误改。

平面底色提取属于可选处理：不满足条件时保留已通过几何验证的普通配准图，并提示重新检查背景与接缝。仍须视觉审核和参考背景/选区外像素校验。此模式只保证选区外无变化，选区内可能保留模型噪点。

参考范围由工具自动计算，界面不提供参考边距输入框或蓝色虚线，仅显示实际修改选区。历史任务的参考参数继续兼容。
